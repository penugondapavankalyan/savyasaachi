# Database Table: `bills`

**Domain:** Billing  
**MCP Owner:** Billing MCP  
**Schema:** `billing`

---

## Purpose

The `bills` table stores **finalized, immutable billing records**. A bill is created when the owner confirms a draft bill. Once created, a bill record is never modified — it is the permanent financial record of a completed transaction.

Bills carry the complete GST breakup (per-item in `bill_items`, totals here), payment information, and link to the khata system for credit transactions.

---

## Schema

```sql
CREATE TYPE payment_mode AS ENUM ('CASH', 'UPI', 'CARD', 'CREDIT');

CREATE TABLE public.bills (
    id                  UUID            PRIMARY KEY DEFAULT gen_random_uuid(),
    store_id            UUID            NOT NULL REFERENCES public.stores(id) ON DELETE RESTRICT,
    bill_number         TEXT            NOT NULL,
    telegram_user_id    BIGINT          NOT NULL,
    workflow_id         UUID            NOT NULL UNIQUE,
    customer_id         UUID            REFERENCES public.customers(id) ON DELETE RESTRICT,
    subtotal            NUMERIC(10,2)   NOT NULL CHECK (subtotal >= 0),
    total_cgst          NUMERIC(10,2)   NOT NULL DEFAULT 0.00 CHECK (total_cgst >= 0),
    total_sgst          NUMERIC(10,2)   NOT NULL DEFAULT 0.00 CHECK (total_sgst >= 0),
    total_discount      NUMERIC(10,2)   NOT NULL DEFAULT 0.00 CHECK (total_discount >= 0),
    total_amount        NUMERIC(10,2)   NOT NULL CHECK (total_amount >= 0),
    payment_mode        payment_mode    NOT NULL,
    payment_reference   TEXT,
    is_credit           BOOLEAN         NOT NULL DEFAULT FALSE,
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);
```

### Column Definitions

| Column | Type | Nullable | Default | Description |
|---|---|---|---|---|
| `id` | UUID | No | `gen_random_uuid()` | Internal primary key. |
| `store_id` | UUID | No | — | FK to `stores.id`. |
| `bill_number` | TEXT | No | — | Human-readable sequential bill number per store (e.g., `BL-2024-001`). Generated by Billing MCP. |
| `telegram_user_id` | BIGINT | No | — | The owner who created this bill. Denormalized. |
| `workflow_id` | UUID | No | — | Carries over from `draft_bills.workflow_id`. **Unique constraint** — the idempotency key. Retried finalization returns the existing bill. |
| `customer_id` | UUID | Yes | — | FK to `customers.id`. Non-null only for credit (`is_credit = TRUE`) transactions. |
| `subtotal` | NUMERIC(10,2) | No | — | Sum of (quantity × unit_price) for all items, before GST. |
| `total_cgst` | NUMERIC(10,2) | No | `0.00` | Sum of all CGST amounts across all line items. |
| `total_sgst` | NUMERIC(10,2) | No | `0.00` | Sum of all SGST amounts across all line items. Equal to `total_cgst` for intra-state. |
| `total_discount` | NUMERIC(10,2) | No | `0.00` | Reserved for Phase 2 (discounts). Always 0 in Phase 1. |
| `total_amount` | NUMERIC(10,2) | No | — | `subtotal + total_cgst + total_sgst - total_discount`. The amount the customer actually pays. |
| `payment_mode` | payment_mode | No | — | How the customer paid: CASH, UPI, CARD, or CREDIT. |
| `payment_reference` | TEXT | Yes | — | UPI transaction ID or card approval code. Optional. |
| `is_credit` | BOOLEAN | No | `FALSE` | If TRUE, this bill was put on credit (khata). `customer_id` must be non-null if TRUE. |
| `created_at` | TIMESTAMPTZ | No | `NOW()` | Immutable. When the bill was finalized. |

> **Note:** There is no `updated_at` column — bills are immutable after creation.

## Bill Number Generation

Bill numbers are sequential per store in the format `BL-YYYY-NNN`:

```sql
CREATE OR REPLACE FUNCTION generate_bill_number(p_store_id UUID)
RETURNS TEXT AS $$
DECLARE
    v_year TEXT;
    v_count INTEGER;
BEGIN
    v_year := TO_CHAR(NOW(), 'YYYY');
    SELECT COUNT(*) + 1 INTO v_count
    FROM public.bills
    WHERE store_id = p_store_id
      AND TO_CHAR(created_at, 'YYYY') = v_year;
    RETURN 'BL-' || v_year || '-' || LPAD(v_count::TEXT, 3, '0');
END;
$$ LANGUAGE plpgsql;
```

## GST Computation

GST is computed **per line item** in `bill_items`, then summed here:

```
For each bill_item:
  taxable_value = quantity × unit_price
  gst_amount    = ROUND(taxable_value × gst_rate / 100, 2)
  cgst_amount   = ROUND(gst_amount / 2, 2)
  sgst_amount   = gst_amount - cgst_amount  ← avoids double-rounding error
  line_total    = taxable_value + cgst_amount + sgst_amount

Bill totals:
  subtotal    = SUM(taxable_value)
  total_cgst  = SUM(cgst_amount)
  total_sgst  = SUM(sgst_amount)
  total_amount = subtotal + total_cgst + total_sgst
```

## Idempotency

```sql
-- Unique constraint on workflow_id — the idempotency key
ALTER TABLE public.bills ADD CONSTRAINT bills_workflow_id_unique UNIQUE (workflow_id);
```

If Telegram redelivers the "finalize" message and the Billing MCP is called again with the same `workflow_id`, the `INSERT INTO bills ... ON CONFLICT (workflow_id) DO NOTHING` returns the existing bill without creating a duplicate or re-decrementing stock.

## Constraints

```sql
ALTER TABLE public.bills ADD CONSTRAINT bills_pkey PRIMARY KEY (id);
ALTER TABLE public.bills ADD CONSTRAINT bills_workflow_id_unique UNIQUE (workflow_id);
ALTER TABLE public.bills ADD CONSTRAINT bills_store_id_fkey
    FOREIGN KEY (store_id) REFERENCES public.stores(id) ON DELETE RESTRICT;
ALTER TABLE public.bills ADD CONSTRAINT bills_customer_id_fkey
    FOREIGN KEY (customer_id) REFERENCES public.customers(id) ON DELETE RESTRICT;

-- Credit bills must have a customer
ALTER TABLE public.bills ADD CONSTRAINT bills_credit_requires_customer
    CHECK (is_credit = FALSE OR (is_credit = TRUE AND customer_id IS NOT NULL));
```
